# Контракт сюжетных данных и сохранений

Статус: предложение, парсер, схемы и тесты ещё не реализованы. Это контракт собственного загрузчика Bekhilitt, а не описание стандартных datapack JSON Minecraft. Расположение будущих файлов — в [карте](PROJECT_MAP.md).

## Идентификаторы и определения

Определения неизменяемы во время сеанса. Идентификатор имеет форму `bekhilitt:golden_age/first_duel`, использует строчные латинские буквы, цифры, `_`, `/` и `-` после namespace; уникален внутри типа. Межтиповые ссылки содержат явный тип. Имя персонажа, перевод, номер файла и UUID сущности не служат сюжетным ID. Переименование требует таблицы миграции; старый ID нельзя отдавать другому смыслу.

| Тип определения | Обязательные поля |
|---|---|
| Глава | schemaVersion, id, titleKey, entryQuestId, questIds |
| Задание | schemaVersion, id, chapterId, titleKey, stages, initialStage, terminalStages |
| Этап задания | id, objectives, разрешённые события завершения, transitions с условиями |
| Сцена | schemaVersion, id, chapterId, participants, regionId, entryNode, nodes, recoveryNode, skipPolicy |
| Узел | id, type, next или terminal; специальные поля своего типа |
| Персонаж | schemaVersion, id, nameKey, presentationId, поведение по умолчанию |
| Регион | schemaVersion, id, dimensionId, bounds, безопасная точка возвращения |
| Представление | id, modelId, animationIds, необязательные soundIds, обязательный fallback |

Типы узлов первого среза: `dialogue` (speakerId, textKey, choices), `cue` (actorId, animationId, длительность и резервный переход по серверному времени), `duel` (combatProfileId, outcomeTransitions), `checkpoint` (effects, next), `end` (terminal). Все названия полей — проект собственного формата.

Условия — ограниченное дерево `all`, `any`, `not`, `flag_equals`, `quest_stage`, `event_received`; эффект — `set_flag`, `advance_quest`, `unlock_region`. Ни скриптов из JSON, ни произвольных Java-выражений. У каждого эффекта постоянный effectId. Выбор пользователя ссылается на следующий узел и условие, а не содержит исполняемый текст. Циклы допускаются только при явном ожидании ввода или события; переходы без ожидания ограничены, чтобы не зависнуть в одном тике.

Иллюстрация терминального узла канонического поединка вступления, **не готовый полный ресурс**. Эти эффекты не применяются к отдельной учебной тренировке первого прототипа: она не завершает `first_duel` и не открывает `camp_intro`. Учебные определения используют отдельные ID и testOnly-профиль по [плану](PROTOTYPE_PLAN.md):

```json
{
  "id": "duel_committed",
  "type": "checkpoint",
  "effects": [
    {"effectId": "first_duel_done", "type": "set_flag", "flagId": "bekhilitt:first_duel_done", "value": true},
    {"effectId": "camp_intro_available", "type": "advance_quest", "questId": "bekhilitt:camp_intro", "stageId": "available"}
  ],
  "next": "end"
}
```

`end`, флаг и задание должны существовать в полном комплекте. Читаемый реестр сцен — [SCENES](story/SCENES.md); он не заменяет будущие игровые определения.

## Проверка перед запуском

Загрузчик сначала разбирает весь комплект в новую таблицу, затем проверяет его целиком и только после успеха публикует. Ошибка сообщает путь файла, JSON-поле, ID и причину. Последовательность проверок:

1. Версия схемы, обязательные поля, типы, ограничения длины, дубли ID и неизвестные поля.
2. Все ссылки на главы, этапы, персонажей, профили боя, узлы, регионы, флаги и эффекты разрешаются; тип значения условия соответствует типу флага.
3. Входной и recovery-узлы существуют; терминалы достижимы; нет автоматических бесконечных циклов; каждый исход поединка имеет переход; skip не обходит обязательный игровой результат.
4. Ключи локализации есть в `ru_ru`; нейтральный fallback есть в `en_us`. Текст — строка перевода, не ID сцены. Проверяются шаблонные параметры перевода.
5. Модели, анимации и обязательные звуки существуют в собранном наборе ресурсов. Сервер проверяет ссылки по манифесту, не загружая рендерер; сборочная проверка сопоставляет манифест с файлами. Отсутствие необязательного звука не блокирует сюжет, отсутствие обязательного ресурса блокирует публикацию контента.

Невалидный комплект не должен наполовину изменять действующий мир. При ошибке начальной загрузки кампания недоступна с понятной диагностикой; существующий снимок не перезаписывается пустым.

## Сохранения и эффекты

Один снимок кампании на мир, включая данные участника; он принадлежит серверу. Предлагаемый адаптер использует Minecraft Saved Data, привязанный к основному миру, даже если игрок меняет измерение. Конкретная схема codec и интеграция сохранения должны быть проверены в P1; [официальное руководство 1.21.11](https://docs.fabricmc.net/1.21.11/develop/saved-data) подтверждает механизм, но не его реализацию здесь.

Поля снимка: schemaVersion, contentVersion, campaignId, participantId, revision, chapterId, questStages, flags, characterRecords, unlockedRegions, activeScene и appliedEffects. `activeScene` содержит sceneId, runId, checkpointNodeId, attemptId и статус. Во время исполнения текущий узел может быть новее контрольной точки; после аварии воспроизводится контрольная точка, а не произвольная середина анимации.

Ключ применения одноразового сюжетного эффекта: campaignId + sceneId + effectId, **без нового runId**. Повтор сцены с другим runId поэтому не выдаёт награду заново. Повторяемые награды вне первого среза требуют отдельной спецификации. CampaignService вычисляет новый снимок целиком: флаг завершения, открытие следующего задания, appliedEffects и revision меняются вместе; адаптер помечает его изменённым. Успех сетевого ответа означает применение в памяти, не гарантию физической записи на диск.

После аварии допускается возврат к последнему успешно записанному снимку. Сюжетные награды не могут сохраниться отдельно от appliedEffects. Предметов, опыта и иных внешних наград в P1–P4 нет. Перед их добавлением нужна проверенная доставка с идентификатором выдачи и восстановлением: простое «дать предмет, затем сохранить флаг» небезопасно. Сохранение Minecraft-инвентаря и кампании нельзя объявлять общей атомарной транзакцией.

Миграции — последовательные преобразования N → N+1 на копии с тестовыми снимками. Перед записью мигрированного мира создавать резервную копию при остановленном сервере. Неизвестная будущая schemaVersion, отсутствующий обязательный сюжетный ID или повреждение запрещают перезапись и запуск кампании; пользователю предлагается восстановить копию. Не начинать кампанию заново молча. Смена contentVersion требует проверки таблицы совместимости ID и контрольных точек; непереносимая сцена откатывается только по явно заданному правилу миграции.

## Прерывания

| Событие | Поведение |
|---|---|
| Обычное сохранение и выход | Сохранить последнюю контрольную точку, освободить временное управление; при входе повторно разрешить NPC и синхронизировать клиента |
| Смерть игрока | Отменить активную попытку, освободить камеру и NPC; после возрождения предложить повтор с recoveryNode без эффекта завершения |
| Поражение в учебном поединке | Серверный контролируемый исход, не обязательно смерть; перейти по outcomeTransition |
| Выгрузка NPC или области | Приостановить/отменить попытку до безопасной контрольной точки, не считать победой и не загружать весь мир |
| Закрытие диалога или отмена | Отправить намерение, сервер применяет recovery-политику; не оставлять игрока с заблокированным управлением |
| Пропуск сцены | Пропускать только разрешённое представление; обязательный поединок не считается выигранным; обязательные эффекты проходят тот же проверенный переход |
| Разрыв соединения | Сервер завершает временную аренду управления; повторное подключение получает снимок, новая попытка имеет новый attemptId |
| Повторный запуск завершённой сцены | Только режим просмотра без эффектов или отказ; журнал эффектов не очищается |
| Сбой до/после применения перехода | После загрузки состояние соответствует одному сохранённому снимку; повтор эффекта по постоянному ключу безопасен |

Зависания предотвращаются явными recovery-переходами и ограничением ожидания NPC/анимации. Ограничение времени ожидания не должно автоматически засчитывать сюжетный успех. Проверки этих правил заданы в [плане](PROTOTYPE_PLAN.md).

## Хронология и доступность возможностей

Определение главы расширяется обязательной карточкой из [CHRONOLOGY](story/CHRONOLOGY.md): editionId, episodeRefs/sourceRefs, presentationOrder, worldOrder/afterEventIds, requiredCompletedEvents, requiredCharacterStates, resultingCharacterStates, allowedEquipmentIds, allowedAbilityIds, revealIds, allowedSideActivities и verificationStatus. Воспоминание имеет flashbackOf и отдельный момент раскрытия. Пустые непроверенные наборы экипировки не означают разрешение всего контента.

Валидатор проверяет существование событий и фактов, отсутствие циклов prerequisite, допустимость перехода персонажа, отсутствие преждевременных reveal/предметов/способностей и смешения testOnly с кампанией. Для каждой дополнительной активности заданы окно доступности и постусловия, сохраняющие каноническую последовательность. Автоматические проверки ловят структурную ошибку, но не заменяют редакторскую сверку эпизода.

В снимок добавляются completedEventIds и revealedFactIds; миграции не выводят их догадкой из номера главы. Профили управления версионируются как контент; привязки клавиш и настройки камеры хранятся отдельно на клиенте, не в сохранении мира. Их сброс не меняет пройденные события.

## Профили развития и боссов

Будущие определения: CharacterProfile (id, schemaVersion, baseStats, abilityIds, sourceRefs), ProgressionPolicy (id, chapter/event prerequisites, caps, allowedUpgrades), EffectDefinition (id, modifiers, stacking, durationPolicy, removalPolicy), BossEncounterDefinition (id, characterId, sourceRefs, regionId, prerequisites, objective, phases, outcomePolicy, retryPolicy). Фаза содержит formId, attackIds, vulnerabilityRules и упорядоченные transitions. Числа и формулы — кандидаты, не утверждённый баланс; неизвестные способности не заменяются универсальной маной.

Валидация: конечные допустимые значения и единицы; отсутствие циклов производных параметров; ссылки на формы/атаки/эффекты; достижимость выхода из фазы; явная обработка прерывания; соответствие разрешённых abilities/снаряжения этапу; отсутствие неограниченного накопления модификаторов. Для production-профиля необходимы проверенные sourceRefs либо явная маркировка допустимого игрового приближения. Непроверенная форма из другой адаптации блокирует приёмку.

ProgressionRecord хранится в снимке кампании: earnedMilestoneIds, selectedUpgradeIds, rulesVersion и grant ledger через appliedEffects. Производные числа пересчитываются, а не сохраняются вторым источником истины. Boss checkpoint содержит encounterId и точку возобновления до попытки; завершённый outcome записывается вместе с сюжетным событием и развитием. Временные эффекты боя сбрасываются при повторе; переносимые сюжетные последствия представлены фактами кампании. Миграции отдельно проверяют смену лимитов главы и удалённые upgradeId, не теряют развитие молча.

## Личная линия сюжетного персонажа

CharacterStoryProfile задаёт id, personalStages, capabilityProfiles, goals, knowledgeRules, relationRules, dialoguePools, presentationProfiles и sourceRefs. Stage содержит prerequisites, разрешённые переходы и действия. KnowledgeRule явно различает witnessed, reported и authored; авторское знание не равно доступному игроку раскрытию. MemoryRecord: eventId, factId, learnedAtEventId, provenance, significance. RelationContext содержит именованные измерения и evidenceEventIds; числовая формула симпатии не задана.

CharacterRecord в снимке кампании содержит personalStageId, knownFactIds, memoryRecords, directedRelations, goalId, activityCheckpoint и capabilityProfileId. Это расширение существующей записи, не второе сохранение NPC. Применение события, изменение отношений и отметка appliedEffects входят в одну ревизию. Временный путь и цель атаки не сериализуются как личность.

Проверки: никакое правило не открывает факт раньше разрешённого события/получения сведений; противоречивые этапы и диалоговые условия исключены; каждое занятие имеет допустимые capabilities, fallback при отсутствии участника и освобождение аренды. Ограниченные необязательные оттенки отношений не открывают обязательный сюжетный переход. Миграции сохраняют основания памяти и не выдают будущие знания по одному номеру главы.

## Герой источник управления и роли

CharacterProfile расширяется ссылками actionSetId, equipmentPolicyId, animationProfileId и cameraProfileId. SceneParticipants — явная таблица roleId → characterId; controlledRole, viewpointRole, speakerRole, cameraSubjectRole и beneficiaryCharacterId не выводятся из UUID подключённого пользователя. PlayableSegmentPolicy задаёт разрешённые главы, сцены и персонажей. До выбора режима разрешён только основной герой Гатс.

ControlBinding и transfer record имеют schemaVersion, transferId, characterId, source, controllerUserId, projectionId, generation, ownershipEpoch, phase и checkpointRef. Валидатор проверяет уникальность активного владельца/проекции, разрешение сегмента и отсутствие ссылки на чужие знания или награды. Личные записи CharacterRecord и CampaignState разделены логически в одном снимке; привязки ввода пользователя в них не хранятся. Правила передачи физического инвентаря требуют отдельного испытания, описанного в архитектуре.
