# Отдельная практика нативных навыков

Реализация экспериментального профиля. Сборка и тесты проверяются отдельно от
игрового QA; наличие этого документа не утверждает успешный игровой проход.

## Доступ и назначение

`/bekhilitt practice` доступна только владельцу уже завершённого первого эпизода,
в одиночном одноразовом мире `Bekhilitt-Test*` с `-Dbekhilitt.dev=true`.
На dedicated server практика запрещена. Это отдельное упражнение до пяти минут:
оно не переигрывает Гриффита, не создаёт новый сюжетный прогресс и не выдаёт наград.
`/bekhilitt stop` возвращает исходное состояние. Выход из лагеря, смена снаряжения,
временных навыков или защитной настройки также останавливает упражнение.

Нужны пустая выбранная рука, пустая вторая рука/броня и пустые слоты MOVER/IDENTITY.
Существующие навыки не заменяются. Выдаётся тот же временный штатный iron greatsword
Epic Fight, а в пустые слоты добавляются `epicfight:demolition_leap` и
`epicfight:meteor_slam`.

## Штатный ввод Epic Fight 21.17.3.1

- Demolition Leap: на земле удержать фактическую клавишу Mover Skill
  (`key.epicfight.mover_skill`, по умолчанию Space), зарядить примерно 0.6–2 секунды
  и отпустить. Взгляд вверх даёт высоту, горизонтально — больше дальности.
- Meteor Slam: в воздухе смотреть вниз минимум на 40 градусов на землю дальше
  шести блоков и коротко нажать Attack. Greatsword поддерживается самим навыком.
  Это нативный перехват обычной атаки, не отдельная кнопка Identity.
- Удержание Attack при общей клавише с Weapon Innate означает другой навык;
  в упражнении нужен короткий клик.

Код не проигрывает эти действия за игрока. Сервер только наблюдает BEGIN штатных
`BIPED_DEMOLITION_LEAP` и `METEOR_SLAM` и сообщает, какие анимации реально начались.
Эти отметки не означают нанесённый урон, сюжетную победу или освоенный навсегда навык.
Предел области: footprint лагеря по X/Z и до 64 блоков над его полом, с учётом
высоты мира. Практика безопасно возвращает игрока при выходе за границу.

## Обратимость и защита мира

Epic Fight `LevelUtil.spreadShockwave` может серверно удалять блоки без collision
над волной при `mobGriefing=true`. Поэтому правило не считается чисто визуальным.
Перед практикой отдельный строгий version-1 lease сохраняет owner/attempt,
исходное mobGriefing и learned-состояние двух навыков. Сохранённый integrated
`level.dat/Data/Player/NeoForgeData` read-verify подтверждается до выдачи навыков
и изменения правила на false. В обычной сюжетной дуэли правило не меняется.

Возврат сохраняет защитный practice marker, пока читаемая запись владельца
не вернёт исходную позицию и game mode с read-verify фактического player save.
При повреждённой campaign/return записи marker не снимается, игрок остаётся
защищённым; исходные координаты и режим не угадываются. После подтверждённого
возврата прекращаются holding/анимация/скорость/накопленное падение, снимаются
только выданные навыки и только временно появившееся learned-состояние. Затем
возвращается исходное true или false, сохраняется мир и проверяется на диске
исходное правило вместе с ещё существующим recovery lease. Только после проверки снимается
запись. Обычный выход и JOIN после crash используют тот же путь. Повреждённый,
неполный или будущий формат не сбрасывается в значения по умолчанию. Само
присутствие practice marker любого NBT-типа включает quarantine вне safe practice:
сервер закрывает native casts и входящий/исходящий entity damage, прекращает
holding/actions до разбора записи. JOIN проверяет этот marker независимо от
читаемости campaign snapshot и dev-флага. Для снятия marker требуется подтверждённый
возврат по читаемой записи кампании; до этого действует quarantine. Клиенту
до удаления MOVER отправляется штатный EXPIRED feedback,
чтобы удерживаемый Leap не ссылался на уже удалённый skill container. Проверка
quarantine выполняется также до native entity tick, а не только после него.
Пока существует practice lease, команда изменения mobGriefing отклоняется;
запрос текущего значения и другие game rules остаются доступны. Это закрывает
смену правила между началом заряда и его нативным отпусканием.

Meteor имеет и оружейный collider, и caster-attributed shockwave, способный
затронуть любые Entity. В отдельной практике `EntityInvulnerabilityCheckEvent`
закрывает исходящий урон игрока по сущностям, включая обычные предметы и декор;
LivingIncomingDamage служит дополнительной границей. Входящий урон игроку также
закрыт. NPC остаются неподвижными. Это безопасная демонстрация движений и эффектов,
а не второй боевой эпизод.

## Если восстановление заблокировано

Сообщение о повреждённой записи означает безопасную остановку: practice marker
остаётся, нативные действия и урон закрыты. Координаты и game mode не выбираются
по умолчанию. Удаление marker вручную снимет эту защиту, но не восстановит игрока.
`/bekhilitt stop` не является командой исправления повреждённых данных.
Обычные `start`, `start disposable` и `resume` также отказывают при любом practice
marker, даже если campaign snapshot отсутствует: новый сюжет не заменяет возврат.

1. Выйдите в меню и полностью закройте клиент. Не продолжайте эксперимент в этом
   мире и не пытайтесь исправить его сменой game mode или удалением NBT-полей.
2. Сохраните отдельную копию всей папки проблемного мира до любых исправлений.
3. Верните согласованную резервную копию **всего этого же мира**, сделанную до
   повреждения. `level.dat`, данные игрока и `data/bekhilitt-first-episode.snapshot`
   должны происходить из одной копии. Не смешивайте файлы разных миров, владельцев
   или попыток. Точечное восстановление snapshot допустимо только при проверке,
   что это его точная неповреждённая копия для оставшихся recovery leases.
4. Откройте мир с теми же закреплёнными зависимостями. Если сохранён незавершённый
   practice lease, вход сначала проверит возврат позиции/режима, затем восстановит
   временные навыки, снаряжение и исходное правило. Защитный marker снимается
   только после успешного возврата. При повторном отказе снова закройте мир.

Без подходящей копии автоматического угадывания исходного состояния нет.
Сохраните проблемный мир для разбора и используйте новый одноразовый тестовый мир;
не переносите из повреждённого мира отдельные recovery-поля.

## Проверки

- Pure attempt: только completed owner; 6000 ticks; поздние/чужие события не
  засчитываются; остановка и наблюдения не меняют campaign snapshot или ledger
- NBT: неизвестная/будущая версия, неполные поля, неверные типы/UUID/booleans,
  устаревший attempt, неверное или отсутствующее правило, повреждённый файл
- Recovery ordering: повреждённая кампания, недоступное измерение или ошибка
  проверки player save не позволяют снять защитный marker
- Правило не считается возвращённым, пока одновременно не читаются его исходное
  значение и всё ещё сохранённый lease
- Для приёмки дополнительно нужны реальный Leap/Slam, stop и controlled-crash
  recovery с проверкой блоков, навыков, game rule и неизменности кампании
