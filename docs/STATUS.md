# Текущее состояние Bekhilitt

Обновлено 12 октября 2026 года. Документация охватывает хронологию, управление, развитие, боссов и Гриффита как второго главного персонажа; игровой мод ещё не реализован.

## Выполнено

- Подготовлена возможность будущего управления Гриффитом: ADR 004, общий контракт действий AI/игрока, профили героев, роли сцен и раздельные личные записи. Способ привязки к Player/NPC предложен с явными рисками сохранения и отображения; режим и передача не реализованы.

- Создан отдельный профиль Гриффита: личная линия, знания, память, отношения, занятия и три перехода по эпизодному справочнику. В архитектуре разделены шесть уровней состояния, приоритеты управления и применение событий. Прямой просмотр и проверка выразительных деталей остаются впереди; реакции помечены как проектные. В P1–P4 добавлены проверки памяти, изменения поведения и восстановления AI; P5 проверяет реакцию на совместное задание.

- Сохранены конституция, карта, конкретная архитектура мода, контракт данных, сюжетные ориентиры, реестр источников, четыре ADR и план прототипа. Навигация — в [PROJECT_MAP](PROJECT_MAP.md).
- Утверждённые требования отделены от инженерных и продуктовых предложений. Точки входа, владельцы состояния, AI/NPC, сеть, бой, сохранения и восстановление описаны как будущая реализация.
- Проверены официальные материалы для Minecraft 1.21.11 и наличие артефактов кандидата Fabric; свидетельства и точный пробел проверки — в [ADR 001](decisions/001-stack.md).

## Проверки и ограничения

При начале работы репозиторий содержал только `.git`; AGENTS.md на диске отсутствовал, переданное пользователем правило codebase-memory сохранено в новом файле. Ветка `codex/bekhilitt-architecture`, коммитов нет; ветка не менялась, пользовательских файлов для перезаписи не было.

codebase-memory: проект отсутствовал в списке, выполнена быстрая индексация без сохранения базы в репозиторий. Проверка покрытия начального состояния показала только исключённый `.git`; отсутствие кода дополнительно проверено файловой системой. Граф не используется как доказательство реализации будущих систем. Markdown проверяется напрямую.

Проверены 19 Markdown-файлов и 96 локальных ссылок между документами; все цели ссылок существуют; JSON-пример синтаксически разобран, ограждения блоков и пробельные ошибки проверены. Содержание сверено по статусам, ID сцен, границам прототипа, дереву пакетов и владельцам состояния. Mermaid-схемы проверены по тексту, отдельный визуальный рендер не выполнялся.

Сборка, запуск игры, игровые тесты, профилирование и реализация валидатора не выполнялись: кода и wrapper нет. Java на машине не проверялась. Точная комбинация стека требует P0. Исходное видео, реплики, актёры конкретных героев и соответствие перевода не сверены; аудио не скачивалось. Локальные изменения не опубликованы и не закоммичены.

## Следующий шаг

Выполнить P0 из [плана](PROTOTYPE_PLAN.md): один минимальный Fabric-мод для 1.21.11, закреплённый wrapper, JDK 21, общая и клиентская точки входа, сборка и отдельные проверки клиента/выделенного сервера. Уточнить ещё не проверенные callback API по исходникам выбранных зависимостей. После успешного запуска обновить README реальными командами и этот файл результатами.

Начало окончательно утверждено: встреча с Соколами, без вступления с Чёрным Мечником. Создан реестр хронологии по эпизодным справочникам; прямой просмотр и проверка экипировки/способностей ещё нужны. Ориентир управления Dark Souls отражён в архитектуре и отдельном стенде P0C; подтверждены средства ввода Fabric, но не готовый контроллер/камера. Геймпад не проверен.

Открытые продуктовые вопросы хранятся только в [CONSTITUTION](CONSTITUTION.md). Они не мешают минимальной технической проверке, но блокируют окончательную приёмку кооператива, постановки канонического поединка, финальных реплик и производительности.

Добавлены реестр кандидатов в боссы и контракты характеристик, временных эффектов, развития и фаз. Подтверждение ограничено справочниками; часть имён и обликов предварительна, прямого просмотра нет. Конфликты охвата не превращены в новые сюжетные встречи. Проверки развития включены в P1/P3; отдельный стенд PB предложен после P4. Код этих систем не реализован.
