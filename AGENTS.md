# Правила работы над Bekhilitt

<!-- codebase-memory-mcp:start -->
For structural codebase exploration, use the installed `codebase-memory` skill.
<!-- codebase-memory-mcp:end -->

- Общайся по-русски. Начинай задачу с этого файла, [PROJECT_MAP](docs/PROJECT_MAP.md) и [STATUS](docs/STATUS.md); затем читай только относящиеся к задаче материалы.
- Перед изменениями проверь Git, ветку и пользовательские файлы. Не затирай чужую работу. Не публикуй изменения без отдельного запроса.
- Для структурного исследования проверь индекс, при отсутствии индексируй репозиторий. Проверяй покрытие всех используемых файлов; пробелы читай напрямую. Отсутствие кода устанавливай также по файловой системе.
- [CONSTITUTION](docs/CONSTITUTION.md) — источник утверждённых требований. Различай утверждено пользователем, предложено, проверено, реализовано и заблокировано. Не превращай гипотезу в решение пользователя.
- У каждого вида сведений одно основное место хранения: см. карту. После изменения обновляй затронутые документы и краткий STATUS; не веди в нём стенограмму.
- Не придумывай API, существующие пути, совместимость, реплики и результаты тестов. Планируемые пути маркируй явно. Точные версии проверяй по официальным источникам.
- Клиент не владеет прогрессом кампании. Соблюдай границы и сохранения из ARCHITECTURE и STORY_DATA даже для одиночной игры.
- Новые значимые решения оформляй в docs/decisions с причиной, альтернативами, последствиями и статусом. Архитектурный план не означает реализованную систему.
- До расширения прототипа пройди критерии его текущего этапа. При работе с репликами используй реестр источников; непроверенные формулировки заменяй пересказом, не выдавай его за цитату.
